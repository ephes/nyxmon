# Python test → Rust test map

Every Python test that pins agent behaviour gets a Rust counterpart or a
fixture case (PLAN.md section 7.1). Each slice updates the rows it covers, so
reviewers can see the coverage per slice. Status: `done` (counterpart exists
and passes), `pending` (planned in the named slice), `n/a` (not agent
behaviour, with the reason).

Fixtures live in `agent-rs/fixtures/` and are generated by
`fixtures/generate.py` (`just rs-fixtures`); `tests/unit/test_agent_rs_fixtures.py`
fails when a committed fixture no longer matches the Python code.
