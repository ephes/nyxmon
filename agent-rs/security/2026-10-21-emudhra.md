# eMudhra trust dependency backport

This security-only branch starts at the released `agent-rs-v0.1.0` source,
`ab349050c4c8848c02dab547ccc0ec39cb34c813`. It does not import subsequent Django,
agent behavior, configuration, protocol or database changes. No new agent version,
tag, GitHub release or deployment is implied by this preparation.

The committed lockfile changes exactly two packages:

| Package | Previous | Fixed |
| --- | --- | --- |
| rustls-webpki | 0.103.15 | 0.103.16 |
| webpki-roots | 1.0.9 | 1.0.10 |

The [webpki security release](https://github.com/rustls/webpki/releases/tag/v%2F0.103.16)
rejects certificate paths containing specifically distrusted intermediate public
keys. The [roots release](https://github.com/rustls/webpki-roots/releases/tag/v%2F1.0.10)
removes emSign ECC Root CA-G3. Both changes are necessary security dependencies;
a system CA update alone does not replace this agent's embedded roots.

In this release source, HTTP checks use `HttpSession::new` → `webpki_roots()`
and Telegram notification HTTP uses `tls_config`; both initialize
`webpki_roots::TLS_SERVER_ROOTS`. TCP/IMAP/SMTP use native roots through
`tls::system_roots`. The verifier update applies to the Rust TLS verification
path too. Existing deliberate verification-disabled monitor settings retain
their existing semantics; this dependency update does not turn them into
verified connections. No live incident-chain rejection is claimed by source
inspection or a successful build.

Builds and releases must retain `--locked`. For local validation, use the already
installed pinned 1.99.0 SDK directly, including absolute `RUSTC`/`RUSTDOC` and its
`bin` directory first on the process PATH, so rustup does not start or download a
toolchain. Use a worker-specific `CARGO_TARGET_DIR` and a verified patched
`CARGO_HTTP_CAINFO` bundle, with certificate verification enabled. Do not change
global toolchain, proxy or trust configuration.

## Proposed release and verification boundary

Subject to release approval, prepare patch `agent-rs-v0.1.1` from this released
baseline plus this security change, without merging unrelated application work.
The existing `.github/workflows/agent-rs-release.yml` supports a manual artifact-only
build before a tag. It builds `x86_64-unknown-linux-gnu` on Ubuntu22.04, checks the
glibc2.35 floor, format, clippy and workspace tests, and embeds the exact source
commit via `NYXMON_AGENT_GIT_COMMIT`. Its smoke checks verify version/provenance;
packaging produces the archive and SHA256. A matching version tag creates the
GitHub release separately. The separate `.github/workflows/ci.yml` Rust job
(`cargo deny --locked check`, pinned cargo-deny against `deny.toml`) must also
pass on the exact source commit before tagging. It has not run locally for this
change because cargo-deny is unavailable; the release workflow alone does not
satisfy that gate. See [release instructions](../README.md#releases).

Before deployment, verify the approved archive checksum and embedded source
commit, preserve the current binary and settings, and use the existing managed
agent switch. Verify current service/check health, then exercise both incident
chains as explicit certificate failures and a successful HTTPS control through
the rebuilt HTTP and notification TLS clients using isolated test fixtures.
Observe normal checks and notification delivery without exposing credentials or
changing production checks for a test. A source lock update, artifact build or
controller install is not evidence that a running agent has discarded old trust.

## Hosted CI bootstrap trust

Python/parity CI pins uv0.13.4. Before any SDK installation, the Rust, parity and
release jobs run `scripts/ci_rustup.py`. It admits only disposable GitHub-hosted
Linux x86_64 runners and checks the OS CA bundle contains neither incident root.
An old bundle fails closed; this helper never upgrades runner OS packages.

The helper uses system curl with explicit admitted CA/TLS verification to fetch
the official Rustup1.29.2 Linux archive, verifies its pinned SHA256, invokes only
the verified offline self-replacement stage, then checks installed SHA256 and
`--help` version. It never invokes the old manager's network self-update. A
job-scoped Bash startup file clears inherited Rustup/Rust compiler dispatch
variables (including Cargo linker/runner overrides) in every later shell step,
then unsets its own `BASH_ENV` so nested build/test shells preserve legitimate
variables supplied by Cargo and rustup. Each new workflow step receives the
startup path afresh. It selects the verified manager homes and
admitted CA bundle. Existing SDK version, release version/provenance and artifact
checks remain in place. Local developer environments and toolchains are outside
this runner-only helper's admission boundary.
